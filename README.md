# N64 Handheld (working title)

Standalone Android N64 emulator built on the **mupen64plus-next** libretro core,
focused on handheld devices (Retroid, Odin, AYN, Anbernic).

## Status
Runs games on real handhelds (Retroid Pocket 3.5 Flip, Odin 2 Portal, Retroid Pocket Duo, Odin 3)
with parallel-RDP on Vulkan (bundled Turnip on Adreno) or GLideN64. No menus yet: games are started
over adb (see CLAUDE.md).

## Layout
```
app/src/main/java/.../MainActivity.kt   Surface + lifecycle, picks core/ROM
app/src/main/java/.../NativeBridge.kt   JNI bindings
app/src/main/cpp/libretro_host.cpp      dlopen core, environment callbacks, run loop
app/src/main/cpp/egl_context.cpp/.h     EGL/GLES3 context + FBO for the core
app/src/main/cpp/audio_out.cpp/.h       AAudio output
app/src/main/cpp/libretro.h             Download from libretro/libretro-common (see below)
```

## Getting the core
Build `mupen64plus_next_libretro_android.so` from
https://github.com/libretro/mupen64plus-libretro-nx (or take it from a RetroArch
nightly), and place it in `app/src/main/jniLibs/arm64-v8a/`.

Copy `libretro.h` from https://github.com/libretro/libretro-common/blob/master/include/libretro.h
into `app/src/main/cpp/`.

- [ ] Present only frames that changed, GLideN64 (parked 2026-11-04: Joey made parallel-RDP the target; GLideN64 is the fallback renderer). - [x] Present only frames that changed, parallel-RDP (the big one). **Default since core 3639398 / app 9cc57ca (2026-11-05); `N64_RDP_SKIP_DUP=0` / `N64_SKIP_DUPES=0` turn it off.** Core `N64_RDP_SKIP_DUP=1`: a refresh is a repeat when the VI registers are unchanged, the RDP drew nothing into the rows the VI reads, and an RDRAM hash of those rows matches (catches CPU drawing); never when interlaced. The hash is only compared once the frame's GPU work has landed in RDRAM (`CommandProcessor::timeline_reached`), else a frame the GPU finished late counted as CPU drawing (GoldenEye, Paper Mario found no repeats); the rows are exact, since a margin made drawing into the adjacent buffer count (SM64, MK64 found a third). The log line says why refreshes were new. Odin 3, repeats found = the game's own rate in 14 of Joey's save spots (SM64/MK64/Paper Mario/Banjo/Snap/DK64/Yoshi/Cruis'n/Conker 300 of 600, OoT/MM 400, Perfect Dark 476; Smash draws every frame, GoldenEye's scene 268 of 300). - [x] Precise smart sync (from gopher64, which marks the exact bytes the RDP draws and checks each CPU access against them): our smart sync locks whole 4 KB pages, and most games hit them every frame (SM64 587, OoT 599 waits per 600), so it costs as much as plain sync (Flip ~20 fps vs async). Likely cause: pages shared between a framebuffer's edge and other data (SM64's z-buffer starts at 0x400, the page of the CPU exception vectors). Core `N64_RDP_SMART_DEBUG=1` now counts faults inside the drawn bytes vs only on a shared page; `N64_RDP_SMART_PRECISE=1` lets shared-page faults through without the GPU wait (that page only). Queued on the Portal: smart vs precise vs async, quick set, screenshots for Snap/Cruis'n/Yoshi/DK64.
